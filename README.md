# Autonomous Neuro-Regulation System for Spaceflight

**Mental stability light-minutes from home.**

Built for **NASA Space Apps Challenge 2026 (Hermosillo)** — Challenge: *"Create Health Monitoring Software for Astronauts on Space Missions."*

## Overview

On a deep-space mission to Mars, one-way light-time communication delays reach 4–22 minutes (and solar conjunction can interrupt reliable links for days). Mission Control in Houston cannot intervene in real time during early signs of astronaut anxiety or acute stress.

This 100% static web prototype demonstrates an **onboard autonomous neuro-regulation console** that detects early multi-signal stress deviations, activates private onboard countermeasures (paced breathing, tactile/pressure regulation, and cognitive grounding), and escalates to crew/Houston **only** when critical red-level criteria are met—without ever transmitting private voice logs or journal text.

> Prototype. Crew data is simulated. Not a medical device.

## Data Architecture

1. **Live NASA Data (via Stateless Proxy):**
   - A minimal, stateless Cloudflare Worker (`src/worker.ts`) exposes `GET /api/horizons` and `GET /api/donki?type=FLR|SEP|GST` on the same origin as the static app.
   - It whitelists only `ssd.jpl.nasa.gov` and `api.nasa.gov`, validates all query parameters, adds CORS headers and `Cache-Control: public, max-age=900` (15 minutes), and stores no user logs, cookies, or analytics.
   - Because `ssd.jpl.nasa.gov` omits `Access-Control-Allow-Origin` headers, the proxy enables live JPL Horizons Mars–Earth ephemeris (`COMMAND='499'`, `CENTER='500@399'`) in the browser.
   - In the browser, `src/nasa.ts` requests live data with a 5-second timeout and caches responses in `sessionStorage`, displaying `Live NASA data (fetched hh:mm UTC)`.
2. **Offline Backup Snapshot:**
   - If live endpoints are unreachable, rate-limited (`DEMO_KEY` 30 req/hr, 50 req/day per IP), or running in a static-only preview without the Worker, the app falls back to `public/nasa-snapshot.json` (generated by `scripts/fetch-nasa.mjs`) and clearly labels it `NASA data snapshot (YYYY-MM-DD)`.
   - During testing on `2026-11-15`, direct CCMC (`kauai.ccmc.gsfc.nasa.gov`) timed out (`> 15 s`), and `api.nasa.gov/DONKI/FLR` returned `404` / `429` under `DEMO_KEY`; the proxy and client handle individual feed failures gracefully.
3. **Simulated Crew & Scenario Data:**
   - All 7 crew physiological/neuroendocrine/cognitive signals, self-report moods, voice log timestamps, countermeasure drift responses, and `Mission day N (simulated)` progression are simulated locally in `src/engine.ts`. Not a medical device.

## Running Locally

**Prerequisites:** Node.js 20+

```bash
npm install
npm run dev
```

### Other Commands

- `npm test` — Run Vitest unit tests for all traffic-light and link-status rules
- `npm run lint` — Run TypeScript type-checking (`tsc --noEmit`)
- `npm run build` — Build static production bundle into `dist/`
- `npm run fetch-nasa` — Refresh `public/nasa-snapshot.json` from JPL Horizons & NASA DONKI

## Deployment

### Cloudflare Pages (Primary)
- **Framework preset:** Vite
- **Build command:** `npm run build`
- **Build output directory:** `dist`

### GitHub Pages (Backup)
A ready-to-use workflow is included at `.github/workflows/deploy.yml` (with `base: './'` in `vite.config.ts`). Enable **Settings → Pages → Source: GitHub Actions** and push to `main`.
